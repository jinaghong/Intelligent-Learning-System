### 10 张表与外键关系

```
dept ◄──── emp ◄──── clazz ◄──── student ────┬──► student_violation  (ON DELETE CASCADE)
 │          ▲                                 └──► student_score ──┐  (ON DELETE CASCADE)
 │          │                                                       │
 │          └──── emp_experience (ON DELETE CASCADE)                ▼
 │          └──── clazz.master_id (ON DELETE SET NULL)           course
 └──── emp.dept_id (RESTRICT)
```

### 外键的删除策略（各有理由）

| 外键 | 策略 | 理由 |
|---|---|---|
| `emp → dept` | RESTRICT | 部门下有员工时不许删，由 Service 层先判断并返回业务错误码 |
| `clazz.master_id → emp` | **SET NULL** | 删老师时班级不该消失，只是暂时没有班主任；用 RESTRICT 会抛难以转成友好提示的外键异常 |
| `student → clazz` | RESTRICT | 班级下有学员时不许删 |
| `emp_experience → emp` | CASCADE | 删员工时工作经历自动删，不留孤儿数据 |
| `student_violation → student` | CASCADE | 同上 |
| `student_score → student` | CASCADE | 同上 |
| `student_score → course` | RESTRICT | 防悬空 |
| `oper_log` / `ai_call_log` | **不建外键** | 审计日志必须在当事人被删除后依然留存 |

### 执行方式

```
mysql -uroot -p --default-character-set=utf8mb4
```

```
source .../db/schema.sql
source .../db/data.sql
source .../db/verify.sql
```

`--default-character-set=utf8mb4` 不能省，否则中文会存成乱码。
`verify.sql` 最后两段会**故意报错**以验证唯一键与外键真的生效，看到 ERROR 是预期结果。

## 八、踩坑记录

### 1. 生成脚本字段错位（差点导致 data.sql 整体失败）

`emp` 种子数据的生成模板把「入职日期」和「部门 ID」写反了，生成出
`..., 3, '1', 2015-03-16, 1)` ——入职日期变成 `'1'`。
若流到执行环节，MySQL 会在该条 INSERT 直接报 `ERROR 1292 Incorrect date value`，整个 `data.sql` 中断。

**修法**：把下标访问 `r[4]` / `r[5]` 换成解构赋值 `([username, name, gender, job, deptId, entryDate, status])`，按名字取值就不可能再错位。

**发现方式**：外键检查**碰巧发现不了它**（错位后的值仍在合法范围内），是靠
「按 schema 类型逐格校验」这条通用检查抓到的。

### 2. 违纪时间格式非法

生成模板写的是 `0${9 + (k % 8)}`，`k=1` 时会拼出 `010:30:00`。
**修法**：`String(9 + k).padStart(2, '0')`。

### 3. Java 括号多写一个

`printf(...)` 只需一个 `)` 闭合，我写了两个，导致 lambda 的花括号 `{` 还没关、
`forEach` 的括号却被提前关掉。javac 报 `[84,89] 需要';'`。

**原因**：我把「表达式式 lambda」的 `"));` 写法抄到了「代码块式 lambda」上——
前者没有花括号所以是两个括号，后者有花括号只需一个。

### 4. 终端编码误判（不是真 bug）

应用日志是 UTF-8、中文完全正常，但用 GBK 解码去读会显示成乱码。
Windows 上 Maven 自身输出走平台编码（GBK），而 Spring Boot 应用日志走 UTF-8，
**同一个日志文件里两种编码混在一起**。

另外：在 `cmd.exe` / PowerShell 里运行应用，控制台是 GBK，中文日志会显示成乱码——
**这只是控制台显示问题，数据本身没问题**。在 IDEA 里运行就正常。

### 5. `spring-boot-starter-validation` 是「别人捎带进来的」

依赖树显示它来自 `springdoc-openapi-starter-webmvc-ui` →
`springdoc-openapi-starter-common` → `spring-boot-starter-validation`。

**含义**：现在可以直接用 `@NotBlank` 等校验注解，但**将来真正开始用它时应该在自己的 pom 里显式声明**——
否则哪天把 springdoc 去掉，校验会莫名其妙失效。

### 6. 篡改 JWT 签名的最后一个字符，验签竟然通过了

`LoginFlowTest` 第 3 项原本用「改掉签名部分最后一个字符」来构造篡改 token，
实测撞上过一次期望 401、实际 200 的偶发失败——不是验签没生效，
而是这次篡改**根本没改到东西**。

**根因**：HS256 签名是 32 字节，base64url 编码后是 43 个字符；最后一个字符里
只有 4 位是有效数据、剩下 2 位是填充位。解码器通常忽略填充位，所以只改末位字符
有约 1/16 的概率解出**完全相同**的签名字节，验签照样通过。

**修法**：改签名段正中间的字符（6 位全部有效），任何改动都必然破坏签名。
**教训**：拿「base64url 末尾字符」做篡改实验本身就不可靠，要动确定为有效位的位置。

### 7. MockMvc 请求体默认按 ISO-8859-1 处理，中文 JSON 变乱码

P4b 测试起手踩：不写 `.characterEncoding(StandardCharsets.UTF_8)` 时，MockMvc 会把带中文的
请求体按 ISO-8859-1 编码，服务端 Jackson 解析失败 → 返回「系统繁忙」。
**看起来像接口写错了，其实是测试自己把请求体搞烂了**。POST / PUT 带中文一律显式 UTF-8。

### 8. MockMvc 的 URL 参数不要去手动编码

EmpFlowTest 里搜「丽」：手写 `URLEncoder.encode("丽")` 拼进 URL，MockMvc 会再编一次，
`%E4%B8%BD` 变成 `%25E4%25B8%25BD`，服务端收到字面量，查询永远 0 条。
**改用 `.param("name", "丽")` 直接设参数，不经过 URL 编码**。

### 9. `response.setCharacterEncoding("utf-8")` 会污染 Content-Type

导出实测：这行会让容器把 `;charset=utf-8` 追加到 Content-Type 后面，
前端按精确值判断类型就失配。xlsx 是二进制，字符编码对它本就没意义；
中文文件名靠 RFC 5987 的 `filename*=utf-8''<百分号编码>` 解决
（注意 URLEncoder 会把空格编成 `+`，响应头里要手工换回 `%20`）。

### 10. 日志里出现从没写过的方法名 `EmpMapper.selectWithCursor`

只有 selectOne 被调用的地方，日志却打印执行了 `selectWithCursor`。
原因：**MyBatis-Plus 3.5.17 的 `selectOne()` 是 default 方法，内部由新的游标接口
`selectWithCursor()` 实现**（已从字节码确认）。以后在日志里见到它不要慌——
那就是你调的那次 selectOne。

### 11. pom.xml 的注释里不能出现 `--`

给新依赖写注释时写了「启动加 `--spring.profiles.active=redis` 切换」，
Maven 直接报 `Non-parseable POM: in comment after two dashes (--)`——
XML 规范规定注释内容里**不允许出现 `--`**（`-->` 提前被当成注释结束符）。

**修法**：注释里提到命令行参数时不写开头的 `--`（改成「启动参数带上 xxx」），
或改用全角破折号。**教训**：XML 里只有 CDATA 和正文能自由出现 `--`，注释不行。

### 12. MockMvc 测不到 multipart 大小限制

上传大小上限是 Tomcat 在**解析 multipart 请求**时执行的，
而 MockMvc 根本不经过真容器（请求对象是 mock 出来的，不解析、不检查大小），
所以「传 3MB 被拒」这条在 MockMvc 里写不出来——只能起真服务用 curl 验。
同类情况还有：`server.port`、`context-path` 相关的行为。
**排查上传 / 容器层问题，一律以真服务探针为准。**

### 13. 测试里「外部写后重读」拿到旧值：MyBatis 一级缓存

`ReportFlowTest` 用例 4（调班 ±1）首跑失败：调班后重读，两班人数与调班前完全一样（8→8）。
两条证据锁定根因：① MyBatis 日志里该语句只打印了 4 次 `Preparing`（应有 5 次）——**重读根本没发 SQL**；
② 用例 3（外部 insert 后首读）是通的——说明「写可见」，问题只出在「同语句重复读」。

**根因**：`@Transactional` 测试里 MockMvc 与 JdbcTemplate 共用连接（用例 3 恰好靠这个机制才能
「未提交也可见」），但同一事务也**共用同一条 MyBatis `SqlSession`**——它的一级缓存（localCache）
会在同语句第二次读时直接命中。`JdbcTemplate` 是绕过 MyBatis 的外部写，MyBatis 只在「自己的写」
时才清缓存，于是重读拿到旧快照。

**修法**：测试里外部写之后显式 `sqlSessionTemplate.clearCache()`（封装成 `clearMyBatisCache()`，附注释）。
**生产无此问题**：每个请求独立事务、独立会话，不存在跨请求缓存。
**教训**：MockMvc + `@Transactional`「共享连接」的便利有它的边界——凡「外部写后重读同一语句」，
先想起一级缓存。

### 14. 测试没加 `@Transactional`，日志泄漏进真实库

P7 上线后第一轮全量测试还是 157/157，第二轮 DbSmokeTest 却红了：
「oper_log 期望 0 行，实际 6 行」。

**根因**：`LoginFlowTest` 从 P2 起就不需要回滚（它只读不写），所以没加 `@Transactional`。
P7 给登录贴上 `@Log` 之后，「登录」从只读操作变成了**写操作**（写 oper_log）——
没有事务接管，日志行就真的提交进了库。第一轮跑完库里多了 6 行，
第二轮 DbSmokeTest 数出来不是 0 就炸了。

**修法**：给 `LoginFlowTest` 补 `@Transactional`（日志行随用例回滚），并清掉已泄漏的 6 行。
**教训**：给一个原本只读的接口加上「写」的副作用时，要回头检查所有调它的测试是否还能保持库干净。
DbSmokeTest 的「oper_log 期望 0 行」在这里充当了泄漏报警器——这就是冒烟测试的价值。

### 15. 引入 Spring AI 后「不带 key 启动失败」

P8 加 `spring-ai-starter-model-openai` 后，默认 profile 直接起不来——starter 的
chat / embedding / image / audio / moderation 自动配置**默认全开**，bean 创建时就要读
api-key，没配就抛异常，整个应用启动失败。

**修法**：`application.yml` 里 `spring.ai.model.*` 全部设 `none`（拔掉插件）；
新建的 `application-deepseek.yml`（deepseek profile）再把 `chat` 按回 `openai`。
**教训**：自动配置既是「默认帮忙」也是「默认添乱」——引一个 starter 前要先想清楚它在什么
条件下装配、失败时会不会拖垮整个应用。**降级设计要从「启动期」就开始，不是只考虑「调用期」**。

### 16. Spring AI 的 base-url 带了 `/v1`，请求变成 `/v1/v1/...` → 404

P8 首次真调用（deepseek profile）直接 404，降级路径被真实触发（status=0 的账也正确记下了）。

**根因**：Spring AI 的 OpenAI 客户端会自动拼接 `/v1/chat/completions`，而我们把
`spring.ai.openai.base-url` 写成了 `https://api.deepseek.com/v1`（DeepSeek 自家 SDK 的
示例用法），拼出来就是 `https://api.deepseek.com/v1/v1/chat/completions`。

**修法**：base-url 只写根域名 `https://api.deepseek.com`。
**教训**：「OpenAI 兼容」不等于「约定完全一样」——客户端拼不拼路径、拼什么路径，
必须以客户端实现为准；拿官方 SDK 的示例配置直接套 Spring AI 会踩这个坑。
这也是「降级 + 审计」价值的现场证明：404 没有把接口搞挂，日志里留下了原始错误。

### 17. 无头 Chrome 里 Element Plus 日期选择器点不开

用 JS 的 `el.click()` / 派发 focus 事件，日期面板始终不展开。原因：组件库依赖真实用户手势，
脚本合成的 click 不算数。改用 CDP `Input.dispatchMouseEvent` 发 `mousePressed` + `mouseReleased`
（带真实坐标），面板才正常弹出并可选日期。

**教训**：测试「组件库交互」时，DOM API 假装点击不够；能用原生输入事件就别用 JS 模拟。

### 18. `offsetParent !== null` 判不出 teleport 弹层是否可见

Element Plus 的下拉/日期面板 teleport 到 `body`，`position: fixed` 时 `offsetParent` 恒为 `null`，
明明显示正常也被判成隐藏。改用 `getBoundingClientRect().width > 0`（配合 computed display）。

**教训**：可见性判断要看布局盒，不要依赖 `offsetParent` 这个对 fixed 元素不成立的旧经验。

### 19. 等「文本出现」等到的可能是上一轮就有的行

员工筛选断言 `waitForTableText('李伟')` 立即通过——初始第一页本来就有李伟，请求还没回来，
脚本就往下走了，行数仍是 10。改为等待确定性状态（`waitForRowCount(1)`、总数变化），再断言内容。

**教训**：等待条件必须「只在目标状态成立」，否则是假阳性。E2E 里最贵的 bug 是测试自己说谎。

### 20. 验收脚本会随实现推进而失效

批次 1 脚本断言「部门管理占位页」；批次 2 部门页落地后，这条断言必挂（实测报错
「部门管理占位页未渲染」）。之后迁到仍为占位的「课程管理」，批次 3 落地时再迁到「操作日志」。

**教训**：E2E 脚本是与页面同步演进的资产，不是一次写死的标尺；每批新页面落地都要回跑旧脚本。

### 21. 固定操作列的宽度不够，四个文字按钮换行

学员表操作列原定 250px，四个「图标 + 文字」链接按钮在 1440 视口下仍放不下——
前三个挤在第一行，「删除」掉到第二行，整张表的行高被撑成两倍。

**修法**：按「图标 14 + 文字 28 + 间距 8 + 单元格内边距」估算总宽，列宽调到 286px，
并把按钮间距从 12px 收到 8px。
**教训**：管理后台的固定列宽不能凭感觉，按钮一多先量宽度；E2E 断言全绿也发现不了
「能点但难看」的问题——截图必须人眼过一遍。

### 22. 审计日志把登录返回的 JWT 原样落库

P7 只脱敏了入参 `password`，`returnValue` 直接 `writeValueAsString(result)`。
登录接口的返回体里带着 `token`，于是日志详情页把一枚可用 JWT 完整展示了出来。

**修法**：返回值序列化后同样递归扫描，`password` 与 `token` 都替换成 `******`；
历史 `oper_log` 用 SQL 定向替换旧 token；用例断言返回值里不含明文 token。
**教训**：脱敏要同时覆盖入参和返回值；凭证可能藏在任意响应字段里，不能只盯密码。

### 23. 手工按组件拆 Element Plus chunk，生产环境初始化顺序错乱

按组件把 Element Plus 拆成几十个 chunk 后，dev 一切正常；生产 build 后登录页空白，
控制台 `TypeError: te is not a function`，来自 `ep-focus-trap` chunk。

**根因**：Element Plus 内部模块存在循环引用（focus-trap / popper / dialog），
按文件粒度硬拆后，跨 chunk 的执行顺序不再有保证。
**修法**：撤回按组件拆包，使用 Rollup 默认分包 + 路由级懒加载；
最大 chunk 558KB / 532KB（gzip 193 / 182KB），阈值调到 1200KB。
**教训**：dev 跑通 ≠ 生产跑通；构建产物必须在 `vite preview` 下做一次真实浏览器验收。

### 24. Vite 开发服务器首次访问新路由触发依赖预构建，整页 reload

批次 3 在 dev 下偶发「学员管理页未渲染」，手动点一次又正常。原因是首次访问带新
Element Plus 组件的路由时，Vite 发现新依赖并整页 reload，E2E 的 8 秒等待正好撞上。

**规避**：验收前预热所有路由，或直接用生产 `vite preview` 跑 E2E；
不要把 dev server 的偶发 reload 当成业务 bug。

### 25. 测试假设审计表为空，真实使用后全量测试变红

P7/P8 用例用 `COUNT(*) FROM ai_call_log` / `oper_log` 断言 0 或 1；P9 浏览器验收
产生真实日志后，10 条用例误报；`DbSmokeTest` 还断言 `oper_log=0`。

**修法**：每例先取基线，再断言「基线 + N」；`DbSmokeTest` 移除审计表的固定行数断言。
**教训**：审计表只增不减，测试必须与历史数据解耦——断言「增量」，不要断言「总量」。

## 九、面试追问清单

每完成一个阶段就往下追加。**这些「为什么」是在做的当下最清楚的，做完三个月后回头想会重新推理一遍。**

### 工程与环境

1. 为什么 `.gitignore` 必须先于任何含密钥的配置文件存在？
   （答：一旦提交进历史，删文件也没用，`git log` 仍能翻出来）
2. Maven 的 `<mirrorOf>central</mirrorOf>` 为什么不用 `*`？
   （答：`*` 会吞掉项目自行声明的仓库如 `repo.spring.io`，导致 404 且报错难懂）
3. 为什么不分 Maven 多模块？
   （答：~10 张表、单数据源，拆模块只增加构建复杂度；用包内抽象接口表达可替换性就够）

### 持久层

4. MyBatis-Plus 分页为什么要单独引 jsqlparser？
   （答：分页插件靠**改写 SQL** 实现，改写前必须能**解析 SQL**；3.5.9 起两者解耦）
5. 分页插件的 `maxLimit` 防的是什么？
   （答：有人把 pageSize 传成 999999，一次查询把数据库和内存拖死）
6. `map-underscore-to-camel-case` 省掉了什么？
   （答：不用给每个字段写 `@TableField("entry_date")`）

### 异常与响应

7. 全局异常处理的价值是什么？
   （答：把散落在 N 处的 try/catch 收拢到 1 处）
8. 为什么业务异常返回 HTTP 200 + `code=0`，而不是 4xx？
   （答：国内主流约定，前端只需处理一种成功响应；代价是 HTTP 层面看不出失败、监控统计不到错误率。主动讲出这个取舍是加分项）
9. 为什么未登录反而返回 401？
   （答：「没登录」是**协议层**问题，让前端拦截器能按状态码统一跳登录页）
10. 兜底 `@ExceptionHandler(Exception.class)` 会带来什么副作用？
    （答：会把 404、405 也揽走，显示成「系统繁忙」，必须单独接出来）

### 认证

11. 为什么用 JWT 不用 Session？
    （答：无状态、天然支持多实例、重启不掉线；代价是无法主动踢人下线）
12. JWT 怎么实现「登出」？
    （答：服务端无处可注销，实际是前端删 token；要强制下线就得维护黑名单——这正是 `logout()` 接口预留的位置）
13. ThreadLocal 为什么必须清理？
    （答：Tomcat 线程循环复用，不清理会导致下一个请求捡到上一个请求的身份）
14. 为什么清理放在 `afterCompletion` 而不是 Controller？
    （答：`afterCompletion` 无论业务代码正常返回还是抛异常都执行）
15. 为什么不能用 `equals` 比较密码？
    （答：库里是 BCrypt 密文，且盐随机导致每次加密结果都不同，字符串比较永远 false）
16. 「用户名不存在」和「密码错误」为什么必须给相同提示？
    （答：提示不同会导致**用户名枚举漏洞**，攻击者能靠试错反推哪些用户名真实存在）
17. BCrypt 的盐和强度存在哪里？
    （答：都在密文里，`$2a$10$` 是算法与强度，后 53 字符是盐+哈希，所以校验时无需额外存盐）
18. `@JsonProperty(WRITE_ONLY)` 和 `@JsonIgnore` 的区别？
    （答：前者允许反序列化接收、禁止序列化输出；后者双向都禁。密码字段要用前者，因为 P4 新增员工还要接收密码）
19. 为什么篡改 JWT 签名的最后一个字符，验签可能仍然通过？
    （答：HS256 签名 32 字节 base64url 编码为 43 字符，末位字符只有 4 位有效数据 + 2 位填充位，
    解码器忽略填充位，末位改动可能碰不到任何有效位；篡改实验必须动确定为有效位的位置）

### P3 / P4 追加（2026-10-10）

20. 复杂查询为什么用 XML mapper 而不是注解？
    （答：动态 SQL 用 `<where>` / `<if>` 可读可维护；SQL 与 Java 分离；注解里拼字符串会变成一团乱麻）
21. `<where>` 标签解决了什么？
    （答：自动省去没有条件时的 WHERE、自动吃掉第一个 AND——不用写 `WHERE 1=1` 凑数）
22. 列表查询为什么必须 LEFT JOIN 不能 INNER JOIN？
    （答：没有部门的员工会被 INNER JOIN 从结果里「抹掉」——数据没丢但界面看不到，最难的 bug 类型）
23. 分页 SQL 为什么必须写 ORDER BY？
    （答：不写排序时 MySQL 的返回顺序是实现细节不是承诺；没有稳定排序，第 2 页可能重复 / 漏掉第 1 页的行）
24. 自定义分页方法为什么第一个参数收 `IPage`？
    （答：分页插件靠识别 IPage 参数接管 SQL——套 LIMIT，另跑一条 COUNT，把结果都写回同一个对象）
25. 工作经历为什么「先删后插」而不是逐条比对差异？
    （答：差异更新要写三段逻辑、还要前端回传每条主键；经历一次就几条，全删重插成本可忽略。
    代价：必须和调用方同事务，先删成功后插失败会丢数据）
26. 「修改时不传密码，老密码不变」——一行特判都没写，靠什么？
    （答：`updateById` 的动态 SQL 只 SET 非 null 字段；不 set 的字段根本不出现在 UPDATE 语句里）
27. `@Valid` 只标在 Controller 参数上就够了吗？
    （答：不够。嵌套对象（exprList）要在字段上再加一个 `@Valid` 做级联校验，否则元素内部的
    `@NotBlank` 全部不执行——空公司名的经历能直接入库）
28. 批量删除为什么不需要 `@Transactional`？
    （答：只有一条 DELETE；两张关联表由外键 CASCADE / SET NULL 在数据库侧原子完成）
29. Excel 导出为什么不能复用分页查询？
    （答：分页导出只会导出当前 10 条，用户以为导全了。导出必须另写不分页查询；
    同时要意识到它一次全读进内存，几十万行要改游标 / 分批查）
30. 导出内容为什么和库里不一样（1/2 变成男/女）？
    （答：导出面向「给人看」；用独立的 EmpExportVO 承担编码翻译 + 列顺序，
    以后 EmpVO 加字段也不会污染导出文件）
31. 中文文件名在下载响应头里怎么处理？
    （答：HTTP 头只能放 ASCII；用 RFC 5987 的 `filename*=utf-8''<百分号编码>`，
    且 URLEncoder 的空格 `+` 要手工换回 `%20`）
32. 测试「改了数据库却什么都不留」是怎么做到的？
    （答：测试类上 `@Transactional`，每个用例跑完回滚；MockMvc 与测试同线程共用连接，
    所以接口能看见用例里未提交的数据——换成真 HTTP（TestRestTemplate）这个技巧就不成立）
33. 日志里从没写过的 `selectWithCursor` 是哪来的？
    （答：MyBatis-Plus 3.5.17 的 selectOne 是 default 方法，内部走游标实现 selectWithCursor）
34. `maxLimit` 防住了什么？没防住什么？
    （答：防住 pageSize=999999 这类大值（615 行实测封顶 500）；没防住负数——
    负数会跳过 COUNT 得到 total=0、LIMIT 被兜底为 maxLimit。参数下限校验才是正解，
    P4 修复后 0 / 负数已在校验层直接拦下——这就是「插件兜底 ≠ 参数校验」的实证）
35. GET 查询串参数的校验失败抛的是哪个异常？
    （答：`BindException`。`MethodArgumentNotValidException` 是它的子类、专管 `@RequestBody`；
    两者要分别接住，否则查询串校验失败会掉进兜底分支变成「系统繁忙」）

### P1b 追加（2026-10-10）

36. `CacheService` / `FileStorageService` 为什么先定接口？
    （答：业务只依赖行为（存/取/上传），换实现不改业务代码；两个实现用 @Profile 互斥装配，
    比 @Primary 少一层「谁赢」的隐藏规则）
37. 为什么用 `@Profile("!redis")` 而不是 `@Profile("dev")` 标默认实现？
    （答：取「非某环境」而不是「列举所有用它的环境」——以后加新环境不用回来补名单，
    漏补的后果是启动即报「找不到 bean」，改法只有一处）
38. Caffeine 官方只有统一过期时间，每条数据不同 TTL 怎么实现？
    （答：自定义 `Expiry` 接口，把值包成「值 + ttlNanos」，过期时长从对象身上现读；

39. 上传文件名为什么全换成 UUID，只保留扩展名？
    （答：防止同名覆盖；用户文件名可能带奇怪字符甚至路径穿越（`../../x`）；

40. 按 `yyyy/MM/dd` 分目录存有什么意义？
    （答：单目录几万文件后文件系统列目录变慢；日期分目录天然可归档可清理）
41. 上传接口要登录，为什么读图片的 `/uploads/**` 必须免登录？
    （答：`<img src>` 是浏览器发的普通 GET，带不了自定义 token 头；不放行全是 401 碎图。
    分清「读免登录、写要登录」——放行的只是读）
42. 静态资源映射为什么写 `file:` 前缀、路径还要转绝对路径？
    （答：`file:` 表示磁盘资源（区别于 classpath:）；相对路径按「启动进程的工作目录」
    解释，IDEA / mvn / 打包运行的目录各不同，绝对路径才稳定）
43. 为什么 `max-file-size` 设了 2MB，`max-request-size` 不跟着设 2MB？
    （答：request 是整个请求体上限，含表单边界等包装字节——也卡 2MB 会让「刚好 2MB」

    （答：不开的话匿名 GET 403，前端图片加载不出来；bucket 若开了「阻止公共访问」，

45. 对象存储和本地磁盘两种实现的「切换点」在哪？
    （答：只在启动 profile——代码、接口、前端所见完全相同；返回的都是完整公网 URL，
    所以前端无需知道文件在哪）
46. `OSSClient` 为什么用 `@Bean(destroyMethod = "shutdown")` 而不是 @Component？
    （答：它需要凭证参数、且只在 oss profile 下才该存在；destroyMethod 让 Spring 关闭时
    优雅释放其内部 HTTP 连接池）

### P5 追加（2026-10-11）

47. 为什么不每次实时 `SUM` 违纪明细，而是在 student 表冗余两个汇总字段？
    （答：列表页每行都要显示违纪次数，实时聚合要给每一行跑子查询 / group by，读放大严重；
    接受冗余换读性能——代价是必须保证同事务同步，且口径上「明细是事实、汇总是缓存」。

    （答：两次读-改-写交叉执行会互相覆盖；把加法写成 `violation_count = violation_count + 1`
    交给数据库执行，由行锁保证原子。这是「check-then-act」竞态的经典案例）
49. 违纪处理为什么必须 `@Transactional`？
    （答：插明细和累加汇总是一件事的半步；没有事务就可能出现「有明细没计数」或

50. 班级列表带班主任姓名为什么必须 LEFT JOIN？
    （答：master_id 允许为 null（暂时没班主任）；INNER JOIN 会把这些班级整行抹掉——
    数据没丢但界面上看不见，和员工-部门是同一个坑）
51. `clazz.master_id` 的外键为什么用 `ON DELETE SET NULL` 而不是 RESTRICT？
    （答：删老师时班级不该消失，只是暂时没有班主任；RESTRICT 会抛难转成友好提示的外键异常）
52. 学科 / 学历这些枚举编码的边界校验为什么钉在 DTO 注解上？
    （答：非法编码在参数层就被拦，进不了 Service 更进不了库；前端下拉框、后端校验、
    数据库注释三处口径钉死，不会漂移）
53. 「结班日期不能早于开班日期」为什么写在 Service 而不是自定义校验注解？
    （答：两个字段之间的关系用注解要写类级 @AssertTrue 绕一圈；一行 if 说清的规则

54. `/clazzs/list` 和 `/clazzs/{id}` 为什么不会路由冲突？
    （答：Spring 匹配时字面量路径段优先于占位符——/emps/export 也靠这条规则活着）
55. 批量删除学员为什么不需要 `@Transactional`？
    （答：只有一条 DELETE，`student_violation` 的 CASCADE 由数据库在语句内原子完成）
56. 课程金额为什么从数据库到 Java 再到 JSON 全程 BigDecimal？
    （答：DECIMAL 精确十进制 ↔ BigDecimal 精确十进制，链路上没有二进制浮点介入；

57. MySQL 的 `no` 是关键字，列名叫 `no` 为什么能跑？
    （答：关键字 ≠ 保留字；`no` 非保留，可直接当标识符。schema 里加反引号是防御性写法。

### P7 追加（2026-10-15）

63. AOP 解决什么问题？不用 AOP 怎么写操作日志？
    （答：日志/权限/事务这类事「和每个业务方法都有关、又和业务无关」，写在每个方法里是几十处重复；
    不用 AOP 就得手写 N 处或在拦截器里统一做——但拦截器拿不到方法级信息（调了哪个方法、入参是什么），
    切面能拿到）
64. `@Around` 里的 `proceed()` 是什么？不调用会怎样？
    （答：proceed 才是「真正执行目标方法」；不调它目标方法一次都不执行——请求返回 null 而业务没跑。
    环绕通知把「方法执行」本身交给了切面，这是它和 @Before/@After 的本质区别）
65. 切面抓到异常后为什么必须原样上抛？
    （答：吞掉异常的话全局异常处理器接不到，前端会收到「200 + 空数据」而不是业务错误提示。
    切面的职责是「旁观记录」，不能改变业务行为）
66. 为什么 `@Valid` 校验失败不产生日志？
    （答：参数校验在「进入方法之前」由 Spring 完成，方法根本没执行，切面自然拦不到。
    想记「参数非法」级别的日志要用拦截器或异常处理器，不是切面）
67. 操作日志为什么不允许 update / delete 接口？
    （答：审计日志的价值就在于「不可篡改的历史」；能被改被删的日志等于没记。
    表设计层面就不建外键（当事人被删日志仍留存），代码层面 Mapper 只暴露 insert/select）
68. 如果要把日志改成异步写（@Async），必须先做什么？
    （答：先把 empId 和 IP 从 ThreadLocal 里**取出来**再提交异步任务——ThreadLocal 不跨线程，
    异步线程里 BaseContext.getCurrentId() 拿到的是 null。这是「异步 + ThreadLocal」的经典坑）
69. 日志里为什么不能记明文密码？怎么做到的？
    （答：日志表是低防护区，谁都能查，明文密码落进去等于泄露；切面序列化入参后递归扫 JSON 树，
    把 password 字段替换成 ******。延伸：返回值里的敏感字段同理——本项目靠 WRITE_ONLY 双层防御）

98. 为什么手工按组件拆 chunk 会在生产环境炸？
    （答：Element Plus 内部有循环引用（focus-trap / popper / dialog），按文件粒度拆
    成独立 chunk 后跨 chunk 初始化顺序不保证，运行时报 `TypeError`。改用 Rollup 默认
    分包 + 路由级懒加载；并且用 `vite preview` 验证真实产物，而不是只看 dev）
99. 审计表相关测试为什么要用「基线 + 增量」而不是总量？
    （答：oper_log / ai_call_log 只增不减，开发时点几下页面就会改变总量。测试先记录
    基线，再断言本次请求新增几行，才能与历史数据解耦）
