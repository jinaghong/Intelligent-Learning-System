## 一、目标与范围

为 P9 看板准备全部后端统计接口：四块核心统计（班级人数、学员构成、成绩、违纪）+ 部门统计，
共 **8 个只读接口**，全部 GET 无参数、需登录。

明确不做（YAGNI）：

| 不做 | 理由 |
|---|---|
| 缓存 | 数据量小（百行级聚合）；且会干扰 Apifox 验收——改完数据立刻查却看到旧数字，像 bug |
| 分页 / 筛选参数 | 列表最多 10 行 |
| Excel 导入导出 | 导入属「写路径」，与统计不同主题，另行安排 |
| 概览数字卡 | 如需再加，成本很低 |
| 前端图表 | P9 |

## 二、接口清单（8 个）

| # | 路径 | 返回（`Result<List<...>>` 里的元素） | 口径要点 |
|---|---|---|---|
| 1 | `/report/clazz-student-count` | `{clazzName, total, maleCount, femaleCount}` | 以 clazz 为准 LEFT JOIN student；空班级以 0 出现 |
| 2 | `/report/student-degree` | `{degree, degreeName, count}` | 封闭枚举 1~6 全出，缺类补 0；按 degree 升序 |
| 3 | `/report/student-gender` | `{gender, genderName, count}` | 男 1 / 女 2 两类全出；缺类补 0 |
| 4 | `/report/course-score` | `{courseName, examCount, avgScore, maxScore, minScore, passRate}` | 以 course 为准 LEFT JOIN；无成绩课程 `examCount=0`，其余为 null |
| 5 | `/report/score-distribution` | `{range, count}` | 固定 5 桶；空桶补 0 |
| 6 | `/report/clazz-violation` | `{clazzName, violationCount, totalPoints}` | 以 clazz 为准 LEFT JOIN 明细；无违纪以 0 出现 |
| 7 | `/report/violation-top` | `{studentName, clazzName, violationCount, violationScore}` | 读 student 的汇总字段；只含违纪者；≤10 条 |
| 8 | `/report/dept-emp-count` | `{deptName, total, activeCount, inactiveCount}` | 以 dept 为准 LEFT JOIN emp；含 0 人部门 |

## 三、关键口径（写进测试钉死）

1. **及格率** = `score >= 60` 的人次 ÷ 考试人次 × 100，保留 1 位小数（BigDecimal、HALF_UP）；
   **恰好 60 分算及格**
2. **分数段边界**：`0-59`（<60）、`60-69`、`70-79`、`80-89`、`90-100`（含 100）
3. **「不丢行」四条**：空班级 / 无成绩课程 / 无违纪班级 / 0 人部门都必须出现且为 0
4. **Top 10 稳定排序**：`violation_score DESC, violation_count DESC, student.id ASC`（P4 排序教训）
5. 成绩类字段全程 **BigDecimal**（DECIMAL ↔ BigDecimal 无精度损失）
6. 中文标签（学历 1初中~6博士、性别 男/女）在 **Service 层翻译**，SQL 只出「编码 + 数量」，
   与现有 `EmpServiceImpl.text()` 风格一致
7. 封闭枚举（学历 / 性别 / 分数段）**缺类补 0**，保证 P9 坐标轴稳定
8. 所有接口返回统一 `Result` 包装；列表不分页

## 五、验收标准（Definition of Done）

### A. 用例（~20 条，TDD 先写先红再转绿，分三批）

**批次一：班级人数 / 学历 / 性别**

1. 班级人数 6 行；每行 `total = maleCount + femaleCount`，与库内直查值一致
2. 新建一个空班级 → 它出现在结果里且 `total=0`（不丢行）
3. 把 1 名学员换班 → 两个班人数各 ±1（事务内构造，跑完回滚）
4. 学历分布：6 行全出、按编码升序、求和 = 48；抽 1 条 `degreeName = 初中`
5. 性别分布：2 行、男 + 女 = 48

**批次二：成绩**

6. 课程成绩 8 行（以 course 为基准，一行不少）
7. 抽查 1 门课的 `avgScore / maxScore / minScore` 与 JdbcTemplate 独立直查一致
8. 及格率公式：构造插入 59.99 与 60.00 两条成绩 → 前者不计、后者计（回滚）
9. 分数段：5 桶全出、求和 = 考试总人次（120）
10. 边界归桶：59.99→0-59，60→60-69，90→90-100（构造用例）
11. 新课程（无成绩）→ `examCount=0`、其余 null、行不丢（构造用例）

**批次三：违纪 / 部门**

12. 班级违纪：逐班 `totalPoints / violationCount` 与明细直查一致；全班求和 = `student_violation` 全表 SUM
13. 无违纪班级出现且为 0（事务内清掉某班违纪后查询，回滚）
14. Top10：条数 ≤10 且降序；与直查前 10 对账；重复查询顺序一致（稳定）
15. Top10 不含无违纪学员（`violation_count = 0` 者不出现）
16. 部门统计：6 部门全出（含 0 人部门）；`activeCount + inactiveCount = total`；全表求和 = 15
17. 无 token 访问统计接口 → 401（抽查 2 个）

## 六、风险与注意

- **种子数据实况待采**：某学历 / 某课程可能缺数据——所有用例常量以活库实算为准
- **及格率除法**：BigDecimal 除法必须显式给 scale + RoundingMode，否则除不尽直接抛异常
- **LEFT JOIN 空侧的 NULL**：`COUNT` 为 0 但 `SUM` 为 NULL，SQL 层用 `COALESCE` 兜 0 或 Java 兜底，
  口径写死进测试
- **所有列表查询显式 `ORDER BY`**（P4 教训）
