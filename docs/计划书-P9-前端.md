## 二、总体架构

### 2.1 一句话架构

浏览器只加载一个 HTML（SPA），Vite 开发服务器把 `/api` 开头的请求转发给后端 8080：

```
Vue 页面（views/）
  └─ api/xxx.js        每个模块只写「调哪个接口、传什么参」
       └─ api/request.js   axios 实例：挂 token、拆 Result、处理 401
            └─ Vite 代理 /api → http://localhost:8080
                 └─ Spring Boot（context-path: /api）
```

### 2.3 请求层约定

`src/api/request.js` 是整个前端唯一发请求的出口：

| 行为 | 实现 |
|---|---|
| 请求前缀 | `baseURL: '/api'`（开发走 Vite 代理） |
| 登录凭证 | 请求头 `tlias-token: <JWT 原文>`，**不加 Bearer** |
| 成功判定 | 后端 HTTP 200 + `code === 1`，拦截器直接把 `data` 返回给页面 |
| 业务失败 | HTTP 200 + `code === 0` → `ElMessage.error(msg)` + reject |
| 未登录 / 过期 | HTTP 401 → 清 token + 跳 `/login?redirect=当前地址` |
| 文件下载 | `responseType: 'blob'` 时原样返回完整 response |
| 静默请求 | 自定义 `silent: true`（健康检查用，失败不弹 toast） |

**为什么 token 也存 localStorage**：请求拦截器不依赖 Pinia，避免 `request.js ↔ store` 循环引用；
页面刷新后 Pinia 重建，但 localStorage 里的 token 还在，用户不用重新登录。

### 2.4 登录态与路由守卫

- 登录成功：`POST /login` 拿到 `{ id, username, name, token }`，再调 `GET /login/me` 补全头像/职位
- token 存 localStorage；用户信息也存一份，刷新不闪
- 守卫规则：
  - 没 token 访问受保护页 → `/login?redirect=原地址`
  - 有 token 访问 `/login` → 首页
  - 每次切换更新浏览器标题
- 退出登录：调 `POST /logout`（失败也继续），清本地 token + 用户，`router.replace('/login')`
  - 后端不维护黑名单，旧 token 在 12 小时有效期内仍可用；这是 JWT 的固有权衡

### 2.5 页面通用约定

| 约定 | 说明 |
|---|---|
| 布局 | 深色侧栏（可折叠）+ 白色顶栏 + 浅灰内容区 |
| 列表页 | 搜索区 → 工具栏（总数/批量操作）→ 表格 → 分页 |
| 加载态 | `v-loading`；无数据用 `el-empty` |
| 错误提示 | 请求层统一 `ElMessage.error`，页面不重复弹 |
| 枚举 | 统一放 `utils/dict.js`，下拉选项与表格标签共用同一份 |
| 日期 | 请求/响应统一 `YYYY-MM-DD`（后端 LocalDate 格式） |
| 金额 | 后端 BigDecimal → JSON number，前端 `toFixed(2)` 展示 |

- 列表不分页（后端设计如此），支持前端按名称筛选
- 新增 / 编辑：只有一个字段 + `@NotBlank` 校验
- 删除：确认弹窗；有员工时后端返回「该部门下还有员工，不能删除」，请求层统一提示

### 3.3 员工管理（批次 2）

- 查询条件：姓名模糊、性别、入职日期区间（闭区间）
- 分页：服务端分页，页码 / 每页条数 / 总数
- 表格：头像 + 姓名 + 用户名、性别、职位、入职日期、部门、状态
- 新增 / 编辑弹窗：
  - 必填：用户名、密码（新增）、姓名、性别、职位、入职日期
  - 密码编辑时留空 = 不修改（后端 `updateById` 只更新非 null 字段）
  - 头像：`el-upload` 自定义 `http-request` → `POST /upload`（字段名 `file`）→ 返回 URL 字符串
  - 工作经历：动态行（开始/结束日期、公司、职位），前端校验完整性 + 日期先后
- 批量删除：多选 + 确认；当前页删空自动回上一页
- Excel 导出：
  - `responseType: 'blob'`
  - 从 `Content-Disposition` 的 `filename*=utf-8''...` 解析中文文件名
  - 若后端返回 JSON 错误（也是 blob），先拆开显示 `msg`，不下载坏文件

### 3.4 课程 / 班级 / 学员（批次 3 计划）

- **课程**：无分页列表、CRUD、编号唯一、金额展示两位小数、有成绩记录不许删
- **班级**：条件分页（名称/开班日期区间）、CRUD、班主任下拉（员工列表）、学科 1~5、状态 1/2、结班日期不得早于开班、有学员不许删
- **学员**：条件分页（姓名/学历/班级）、CRUD、批量删除、详情含违纪明细、违纪处理弹窗（扣分 + 事由）
- AI 学习建议入口放在学员详情（批次 4）

### 3.5 操作日志 / AI（批次 4 计划）

- **操作日志**：分页、状态标签、展开行显示 `methodParams` / `returnValue`（字符串 JSON 格式化）
  - 注意：登录日志的 `returnValue` 含 token，展示时不要复制或外传
- **AI**：
  - 学员详情「生成学习建议」→ `GET /ai/advice/{studentId}`，展示 `model`（mock / deepseek-flash / FALLBACK）
  - 课程页「智能出题」→ 选择课程 / 题量（1~20）/ 难度（1~3），展示题干、选项、答案、解析

## 五、关键设计决策（为什么）

1. **为什么用 JavaScript 不用 TypeScript**：Vue 模板 / 组件 / 路由 / 状态已经四个新概念；TS 再加 interface / 泛型 / 类型报错，学习曲线过陡。等 Vue 熟后再迁移。
2. **为什么不做通用表格组件**：5 个列表页只是「长得像」，筛选字段、操作按钮、弹窗都不同。先各写各的，重复到第三处再抽——零基础阶段读得懂比少写几行重要。
3. **为什么 Pinia 只放登录信息**：只有登录态需要跨页面共享；列表/筛选条件属于当前页面，放组件内，避免全局状态污染。
4. **为什么请求拦截器直接读 localStorage，不读 Pinia**：避免 `request.js` 与 `stores/auth.js` 循环引用；页面刷新也不依赖 Pinia 初始化顺序。
5. **为什么 `defineModel` 管弹窗开关**：父组件 `v-model="dialogVisible"`，子组件 `const visible = defineModel()`，少写 `props + emit('update:modelValue')` 的样板代码。
6. **为什么工作经历编辑时总是提交数组**：后端约定 `null` = 不动、`[]` = 清空、非空 = 整体替换；前端永远给数组，语义最清楚，也支持「全部删除」。
7. **为什么日期统一 `value-format="YYYY-MM-DD"`**：后端 `LocalDate` 只认 `yyyy-MM-dd`；不让 Element Plus 默认 Date 对象进请求体。
8. **为什么导出要手动解析 `filename*=utf-8''`**：HTTP 头只能是 ASCII；后端用 RFC 5987 编码中文文件名，前端必须 `decodeURIComponent`，否则文件名是一串 `%E5%91%98...`。
9. **为什么头像上传用自定义 `http-request`**：后端 `/upload` 返回的 `data` 是 URL 字符串，不是 Element Plus 默认期望的对象；自定义请求才能把 URL 直接写进表单。
10. **为什么健康检查要 `silent`**：右上角「系统正常/服务异常」是探针，后端没起来时不该弹「网络异常」打扰用户。
11. **为什么图表 option 用 `computed`**：接口数据一变，ECharts option 自动重算；`ChartCard` 内部 `watch(option)` 调 `setOption`，页面不用手写刷新逻辑。
12. **为什么登录后要再调 `/login/me`**：`/login` 只返回 id / username / name / token，没有头像和职位；再查一次补全顶栏显示。

## 七、风险与待办

1. **构建 chunk > 500KB**：Element Plus / ECharts 全量引入。批次 4 用按需引入 + manualChunks 优化。
2. **上传 URL 固定 localhost:8080**：后端 `storage.local.base-url` 是本机地址；部署时改成公网域名。
3. **无 CORS**：开发靠 Vite 代理；生产建议前后端同源（Nginx 反代 `/api`）。
4. **后端 PUT 的 null 语义**：`deptId` / `clazzId` / `masterId` 传 null = 不修改，前端无法「取消分配」；UI 暂不提供清空按钮。要支持需后端加显式清空语义。
5. **AI 前端入口未做**：批次 4；当前后端默认 Mock，切 `deepseek` profile 才是真实模型。
6. **没有角色权限**：后端所有登录用户权限相同，前端不做菜单级权限。
7. **日志 / 报表没有筛选参数**：前端只能按后端现有条件做；日志只能分页拉取。
8. **分页上限 500**：后端 `maxLimit=500`；前端 pageSize 选项 10/20/50，不会触发上限。

## 八、前端面试追问（P9 追加）

1. Vite 为什么比 Webpack 开发服务器快？
   （答：开发时浏览器原生 ESM 按需加载，只编译当前模块；依赖用 esbuild 预构建。生产仍用 Rollup 打包）
2. Vue3 Composition API 和 Options API 的区别？
   （答：Composition 按「逻辑」组织，相关代码放一起、可抽 composable 复用；Options 按 data/methods/computed 分块，逻辑一多就分散）
3. `ref` 和 `reactive` 怎么选？
   （答：基本类型用 ref；对象/数组两者都行。ref 通过 `.value` 访问，reactive 直接访问但解构会丢响应性）
4. `computed` 和 `watch` 的区别？
   （答：computed 是「派生值」，有缓存、只读；watch 是「副作用」，值变化时执行异步/开销大的操作）
5. 组件上的 `v-model` 是怎么实现的？
   （答：默认 prop `modelValue` + emit `update:modelValue`；Vue 3.4+ 可用 `defineModel()` 简化）
6. 路由守卫怎么防未登录？
   （答：`beforeEach` 里读 token，没有就 `next('/login?redirect=...')`；有 token 访问登录页则跳首页。守卫只做跳转，真正的接口保护在后端）
7. Pinia 和 Vuex 的区别？
   （答：Pinia 去掉了 mutations，action 直接改 state；TS 支持更好、模块化更自然；Vue3 官方推荐）
8. Axios 拦截器在本项目做了什么？
   （答：请求拦截挂 `tlias-token`；响应拦截判断 `code===1` 拆 data；401 清 token 跳登录；blob 请求放行；`silent` 静默）
9. 为什么后端业务失败也是 HTTP 200？
   （答：国内主流约定，前端只处理一种成功响应；代价是 HTTP 层看不出错误、监控统计不到错误率。这是主动讲得出的取舍）
10. token 放 localStorage 有什么风险？
    （答：XSS 能读 localStorage；更安全的方案是 HttpOnly Cookie + CSRF 防护。本项目是练手 + 内网管理后台，选择简单方案，面试要能讲清取舍）
11. Excel 导出的 blob 下载怎么做？
    （答：`responseType: 'blob'` → `URL.createObjectURL` → 创建 `<a download>` 点击 → `revokeObjectURL`；文件名从 `Content-Disposition` 的 RFC 5987 字段解析）
12. 头像上传的 multipart 字段名是什么？为什么不用默认上传？
    （答：字段名 `file`；后端返回 URL 字符串，默认上传组件期望对象，所以用 `http-request` 自定义）
13. ECharts 实例为什么要 `resize` 和 `dispose`？
    （答：容器尺寸变化（侧栏折叠/窗口缩放）不 resize 会变形；组件卸载不 dispose 会泄漏 canvas 和事件）
14. 8 张图怎么保证不丢数据？
    （答：后端统计「以主表 LEFT JOIN + COALESCE 补 0」；前端空数组显示「暂无数据」，`allSettled` 让单图失败不影响其他图）
15. 为什么前端枚举要单独维护一份？
    （答：后端传数字编码，前端下拉和表格都要翻译；集中到 `utils/dict.js`，避免每页各写一份导致口径漂移）
16. 构建 chunk 过大怎么优化？
    （答：Element Plus / ECharts 按需引入；`manualChunks` 拆 vendor；路由懒加载已经做了）
17. 前端怎么验收？
    （答：`npm run build` + 无头 Chrome CDP 脚本：真实登录/点击/上传/导出，断言 DOM、网络头、控制台错误，截图存证；测试数据脚本自清理）
18. 为什么测试里等「文本出现」不够？
    （答：初始页可能本来就有该文本（如李伟在第一页），会提前通过；要等「行数/总数变成目标值」这类确定性状态）

```bash
cd tlias-backend
mvn spring-boot:run
```

cd tlias-frontend
